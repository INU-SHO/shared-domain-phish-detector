Detecting Phishing on Shared-Domain Hosting Services
Using LLM-Based Contextual Mismatch Reasoning

Sho Inuzuka1, Takaaki Toda1,2, Daiki Chiba3, Tatsuya Mori1,2,4
1Waseda University, 2RIKEN AIP, 3Tokyo Metropolitan University, 4NICT
Published Paper (coming soon) Preprint (coming soon) Code

Abstract

Phishing attacks that exploit shared-domain hosting services (SHSs) are increasing. On these services, many independent user sites coexist under the same provider-managed domain, making conventional URL- and domain-based detection features ineffective.

To address this challenge, we leverage large language models (LLMs) and propose an LLM-workflow-based detection method consisting of three components: Brand Analyzer, Content Analyzer, and Judge. The proposed method classifies pages based on the contextual mismatch arising from the combination of:

  • Brand popularity
  • Prompts for sensitive actions

The method also outputs the rationale behind its verdict to improve explainability.

Challenges of Conventional Methods

ML-based methods such as FreePhish have two key limitations when applied to SHSs.

Difficulty of service-agnostic detection

Because URL and HTML structures vary across SHS providers, models trained on a specific set of services are prone to distribution shift on unseen services, limiting their ability to generalize across diverse SHSs.

Inability to capture contextual mismatch

A page on an SHS that strongly indicates a specific brand while prompting sensitive actions exhibits a contextual mismatch that can serve as a detection cue. However, ML-based methods, which operate on correlations among individual features, struggle to capture this higher-level contextual signal.

Proposed Method

The proposed method is organized into two stages: data preprocessing and an LLM workflow. The method takes as input a URL, its corresponding screenshot, and a DOM snapshot, and outputs a verdict on the target's maliciousness along with the rationale leading to that decision.

Data Preprocessing

The raw inputs are transformed into a set of structured representations suitable for LLM-based analysis. Specifically, the stage produces four elements:

  • Apex Domain: extracted from the URL.
  • Screenshot Wordlist: obtained by applying optical character recognition (OCR) to the screenshot.
  • DOM Title: extracted from the <title> element.
  • Parsed DOM: obtained by removing non-content elements from the DOM.

LLM Workflow

The LLM workflow consists of three components that operate in a structured pipeline.

Brand Analyzer

Estimates the brand indicated by a given page and quantifies its popularity using both the LLM's internal knowledge and a web search API.

Content Analyzer

Summarizes the page content, describes its structure, and identifies elements that prompt users toward sensitive actions.

Judge

Integrates the outputs of both analyzers in the context that the page is hosted on an SHS, evaluates the contextual mismatch arising from the combination of brand popularity and prompts for sensitive actions, and produces the final verdict with its rationale.

Datasets

We evaluated the proposed method on two test datasets: the Impersonation dataset and the Non-impersonation dataset.

Impersonation Dataset

The Impersonation dataset contains malicious sites that impersonate well-known brands. As shown in table (a) below, the dataset consists of two conditions: 5 services included in FreePhish's training data (Seen services) and 5 services not included (Unseen services). For each service, we collected 5 benign and 5 malicious samples, yielding 100 samples in total (table (b)). This dataset includes only impersonation-based phishing sites as malicious samples.

Non-impersonation Dataset

The Non-impersonation dataset contains malicious sites that do not impersonate well-known brands. Rather than impersonating brands, these pages appear as ordinary benign pages unrelated to the malicious content they distribute (e.g., yoga or photography pages). They function as link-based doorways that lead visitors to multiple malicious external resources, typically through lists of outbound links or embedded PDF documents. The dataset consists of 14 samples (5 benign and 9 malicious) collected from a single Seen service.

Case Study

The following is a case in which the proposed method (GPT-4.1-mini) correctly classified a phishing site on an SHS as Malicious. The phishing site is a login page impersonating AT&T, a major U.S. telecommunications provider. Below are the outputs of each component.

Brand Report
from Brand Analyzer
Indicates Brand
true
Brand Name
AT&T
Brand Popularity
high
Content Report
from Content Analyzer
Summary
This appears to be a login page asking users to enter their User ID and Password to sign in, likely for accessing an AT&T Mail service, based on visible prompts and labels.
Structure Notes
The page structure is typical for a login form with input fields and a submit button within a centered layout. The DOM and screenshot show consistent labeling and no structural anomalies.
Sensitive Action Prompting
Prompted action: authentication / credential entry. Mechanism: on-page form with text inputs for "User ID" and "Password", and a prominent "Continue" button.
Final Report
from Judge
Final Verdict
Malicious
Rationale
  • The website impersonates a well-known brand (AT&T) hosted on a free hosting domain (weebly.com), which is a contextual anomaly and inherently suspicious given the brand and hosting context rules.
  • The page prompts a sensitive action, specifically authentication credential entry (User ID and Password for sign-in), which combined with the well-known brand indication on free hosting is a strong indicator of malicious intent as phishing.
